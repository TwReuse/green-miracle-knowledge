# 公開知識庫如何分階段落地

## 第零階段：法人與權限

- 決定遠端 GitHub 組織與 Repo 所有權。
- 正式指定知識治理、資料證據、隱私權利及發布角色。
- 決定文字、程式碼、資料與視覺素材授權。

## 第一階段：可信任基線

- 核對法人資料、歷史時間軸、服務流程及現行聯絡入口。
- 以 2018 年後官網資料庫與公開紀錄作為營運成果追溯基準；2018 年前不全面補造明細。
- 建立年度成果 SSOT（單一真實來源）、狀態字典、統計定義、去重及更正機制。
- 建立照片、Logo、引言及合作描述的授權矩陣。
- 完成新成員、內容發布與資料隱私基礎教材。

## 第二階段：公開應用

- 由 Repo 產出官網內容、組織介紹、企業合作包與標準簡報。
- 為公開知識提供 JSON／YAML 索引及版本。
- 建立網站、簡報與 AI 的來源 ID 引用方式。

## 第三階段：影響與協作

- 發布具方法的年度成果與影響力報告。
- 建立社區整修、企業 ESG 及青年數位素養的教育模組。
- 追蹤內容新鮮度、服務轉換、合作詢問與錯誤更正時間。

## 第四階段：官網資料與 AI 整合

### P0：可被信任地引用

- 建立公開資料目錄、穩定公開識別及版本化 JSON／CSV 匯出候選。
- 每份資料附期間、狀態、統計定義、去重方式、產生時間、來源網址與更正狀態。
- 在正式資料庫與公開資料之間完成去識別、欄位最小化及人工核定。

### P1：可被安全地同步

- Repo 讀入前先產生差異清單，保留上一版並由資料 Owner 核定。
- 同步紀錄包含來源版本、資料筆數、增刪修摘要、結果與核定者。
- AI 只使用公開資料與 `approved` 知識卡，不直接讀寫正式資料庫。

### P2：可被用來改善服務

- 協助申請缺件說明、客服查詢與進度溝通。
- 分析物流等待、整修重工、可再生率、保固故障及結案缺口。
- 產生年度成果與合作摘要草稿，重大數字及公開故事仍由人員核定。

本階段目前是[官網資料與 AI 整合需求輸入](governance/website-data-provenance.md)，不是已核定 API（應用程式介面）、資料模型、架構或工期。
