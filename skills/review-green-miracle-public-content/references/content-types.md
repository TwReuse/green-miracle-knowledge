# 內容類型與目的

每頁只指定一個主要類型；可記錄次要用途，但不要用一篇文章同時承擔所有任務。

| 類型 | 核心任務 | 必備內容 | 常見失敗 |
|---|---|---|---|
| `entry` | 幫第一次來的人選路徑 | 一句話定位、角色入口、當期服務連結、閱讀順序、網站邊界 | 只有故事，找不到下一步 |
| `wiki` | 快速理解可引用知識 | 定義、重點、限制、版本或查詢來源 | 內部 ID 太多、像治理規格 |
| `story` | 用事件與人物傳達歷程 | 時間背景、轉折、共同參與者、事實限制 | 英雄化、虛構因果、混淆法人時間 |
| `service` | 理解流程與採取行動 | 角色、步驟、條件、例外、風險、官網入口 | 把說明寫成保證、缺人工轉接 |
| `impact` | 解釋成果與方法 | 期間、母體、狀態、方法、限制、可比較性 | 不同口徑直接相加、過度宣稱 |
| `activity-archive` | 保存可追溯且可再利用的事件 | 日期、角色、目的、行動、結果、證據、權利、學習、後續 | 只有照片與感謝文，無法查找或傳承 |

若內容只是未核定片段，先放來源系統或內部整理區，不要為了「有一頁」而建公開文章。
