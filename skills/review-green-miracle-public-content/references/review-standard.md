# 公開內容優化檢核標準

## P0：發布阻擋 Gate

任一項不合格時，狀態只能是 `revise`、`archive-only` 或 `withdraw`。

1. **事實邊界**：重要主張有核定母稿或可說明的來源；2004 服務起源與 2021 法人化不混稱。
2. **現況邊界**：當期申請、回收、勸募、費用、保固及聯絡方式回到官網，不用歷史稿取代現況。
3. **數字治理**：標示期間、地區、合作方、設備類型、狀態、母體與去重；產能不等於交付。
4. **隱私與權利**：無個資、兒少識別、私密網址、後台明細、未授權照片、Logo 或長篇第三方著作。
5. **組織與核定**：協會與矽聯科技、啟禾扶輪社及其他夥伴的獨立關係正確；最終核定者為 Chinwen。
6. **狀態誠實**：未經 Chinwen 核定不得標示 `approved`，也不得捏造 `approval_evidence`。
7. **年度與價格主張**：年度頁具 `observation_year`、`evidence_cutoff`、來源 ID 與引用限制；採購報價不得改寫成市場平均或實際決算，區間與計算可重算。

## P1：角色任務 Gate

每項以 0、1、2 分評分：0 為找不到或誤導，1 為找得到但費力，2 為清楚可完成。適用項目平均至少 1.6，且不得有 0 分，才可送 Chinwen。

- 30 秒內理解組織、服務與價值。
- 2 分鐘內找到角色所需下一步。
- 能區分知識站的長期脈絡與官網的當期服務。
- 能理解重要限制，不把申請、回收或合作誤認成保證。
- 能找到適合的延伸閱讀或人工確認方式。

## P1：內容品質 Gate

- 標題直接表達讀者問題，開場先給答案或場景。
- 每段只處理一個概念；長段落拆分，避免制度術語主導公開文章。
- 連結文字描述目的，不只寫「按這裡」或裸網址。
- 故事呈現團隊、合作夥伴、整修、物流、志工與社群共同建立，不英雄化。
- 結論與行動相連；文章結尾說明資料邊界或下一步。
- MkDocs 主選單與內頁 H2 目錄以 8 個可見字元內為主，名稱長度與語法保持一致。
- 側邊目錄從 H2 開始，頁面 H1 只在正文顯示一次。
- 同一頁的提示框標籤、段落起句與小標避免重複；重複內容改為專屬短語、合併或刪減。
- 核准對外文章直接提供正確資料與適用範圍；禁止式審稿清單、內部管理要求及討論過程只留在母稿、治理文件或 Skill。
- 對外引用說明提供可直接採用的完整格式與口徑，不要求讀者從錯誤示例反推正確寫法。

## P1：歸檔與再利用 Gate

- 有穩定 `doc_id`、`page_type`、狀態、Owner、知識 ID、審視日。
- 活動另有事件日期、地點或服務範圍、參與角色、目的、行動、結果口徑與公開證據。
- 記錄素材權利與隱私判斷；兒少只保存去識別內容。
- 說明本次經驗可供哪個服務、訓練、簡報、官網或未來研究再利用。
- 發布後保留網址、版本及更正／撤回記錄。

## P2：維護性 Gate

- 服務型與聯絡資訊 90 天內審視；一般歷史文章 180 天內審視，或依風險縮短。
- 內部母稿改變時，可由 `canonical_knowledge_ids` 找到所有衍生頁面。
- 頁面沒有連到公開網站未建置的內部相對路徑。
- 在窄螢幕可讀；表格不承載主要敘事，流程圖提供文字替代。

## 報告判定

- `revise`：有 P0 blocker，或 P1 任一項 0 分。
- `ready-for-Chinwen-review`：P0 全過、P1 達標且已列明待核定項。
- `archive-only`：有傳承價值，但權利、時效或來源不足以公開。
- `withdraw`：錯誤、隱私或權利風險無法合理消除。
