# 綠色奇蹟公開內容優化審核

## 核心原則

把頁面當成一項讀者要完成的任務，不只校正文句。先判斷內容類型與對象，再檢查事實、角色體驗、行動路徑、引用、權利、歸檔與維護性。

將 Chinwen 視為最終事實與治理核定者。無論檢查結果多完整，最高只能建議 `ready-for-Chinwen-review`；不得把頁面改為 `approved`，也不得建立虛構的核定證據。

## 啟動前必讀

1. 讀取 `references/content-types.md`，選定一個主要內容類型。
2. 讀取 `references/review-standard.md`，逐項執行適用 Gate。
3. 若輸入來自 Notion、官網、Blogger、行政統計或後台資料，讀取 `references/fragment-intake-policy.md`。
4. 若要產生審查報告，複製 `assets/page-review-template.md`。
5. 若內容是活動、捐贈、合作或成果記事，另使用 `assets/activity-archive-template.md`。

## 工作流程

### 1. 確認目的與來源邊界

- 說明頁面的主要對象、希望讀者完成的任務及主要內容類型。
- 讀取頁面 front matter、關聯知識母稿、來源 ID 與官網當期頁面。
- 將已知事實、推論、假設、待驗證與建議分開。
- 不把公開新聞背景推成綠色奇蹟直接參與的證據；不為早期歷史補造不存在的逐筆明細。
- 不把 Notion 私密網址、個資、兒少識別、後台明細、合約或內控資料複製到公開 Repo。

### 2. 執行機械檢查

在 Repo 根目錄執行：

```powershell
python -X utf8 skills/review-green-miracle-public-content/scripts/audit_public_page.py public-site/public/<page>.md
```

把腳本結果視為初篩，不得取代人工判斷。先修正 blocker，再處理 warning。

### 3. 模擬角色任務

至少使用與頁面相關的三種角色；入口頁必須使用全部五種：

- 初次訪客：30 秒內能否說明「是誰、做什麼、為什麼重要」。
- 設備捐贈者／企業：2 分鐘內能否找到回收方式、限制及下一步。
- 申請者／社工：2 分鐘內能否找到申請入口，且不誤認保證核配。
- 媒體／教師／內容工作者：能否找到可引用版本、限制及當期查詢來源。
- 新進人員／志工／合作夥伴：能否理解能力、角色邊界及從哪裡取得內部教材。

記錄每個角色的任務、找到的答案、卡點與具體修改，不只寫主觀感受。

### 4. 改善內容

- 保留核定事實與限制，改善標題、開場、段落順序、連結文字與行動指引。
- 入口頁優先提供一句話定位、當期服務入口、角色路線與短閱讀順序。
- 歷史頁明確區分 2004 年服務計畫起源與 2021 年協會法人化。
- 服務頁將條件、例外、風險、客服或人工確認放在承諾旁邊。
- 成果頁區分申請量、回收量、可整修量、產能、完成整修、交付及受益，不直接相加。
- 活動歸檔保存時間、角色、目的、行動、結果口徑、公開證據、權利與可傳承經驗。

### 5. 產出結果與狀態建議

輸出一份完整報告，包含：結論、頁面目的、角色測試、Gate 結果、阻擋項、已完成修改、仍待 Chinwen 核定事項、發布／歸檔建議與下次審視日。

只使用以下建議狀態：

- `revise`：仍有阻擋發布的問題。
- `ready-for-Chinwen-review`：已通過初審，但尚未取得最終核定。
- `archive-only`：適合作為內部歷史素材，不宜直接對外發布。
- `withdraw`：權利、個資、錯誤或時效風險無法在本輪消除。

## 完成條件

- 所有 P0 blocker 已消除或清楚列為待核定，不以文字美化掩蓋。
- 角色任務有可重複的檢查紀錄。
- 對外頁面沒有內部維護路徑、私密來源或失效的隱藏頁連結。
- 當期服務連回官網，長期脈絡留在知識庫。
- 活動內容已決定發布、送審、僅歸檔或撤回，不停留在無狀態檔案。
- 報告明確寫出「最終事實與治理核定：Chinwen」。
