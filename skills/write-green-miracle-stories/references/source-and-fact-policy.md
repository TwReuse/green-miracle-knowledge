# 來源與事實政策

## 成果數字的五分類

對每個數字先標記 `completed-delivery`、`partner-reported`、`annual-target`、`capacity` 或 `referral-impact`，再決定文字。不得把申請量、目標、產能或轉介量寫成實際交付，也不得跨合作體系直接加總。

- 年度實績優先回查官網勸募徵信與結案報告。
- 企業、專案與代整修合作未必納入協會自行捐贈成果，另列支持與影響力。
- 沒有可去重台帳時，不寫 2004 年起累計。
- 不使用「全台最大」；流程完整性改用可驗證的服務環節描述。

## 優先順序

1. 法人、政府、法院、正式核定文件。
2. 事件同期的合作方、學校或機構資料。
3. 協會正式成果、作業紀錄與官方網站。
4. 具採訪責任的新聞或原始影音。
5. 組織自述、Notion、訪談與後見敘事。
6. 搜尋摘要、轉載、社群貼文及其他線索。

沿用 `registry/history-events.yaml` 的 A、B、C、D、O 證據層級，不另建平行分級。層級表示來源性質，不等於公開授權，也不自動表示主張正確。

## 主張狀態

| 狀態 | 意義 | 可否寫入公開正文 |
|---|---|---|
| `confirmed` | 正式來源直接支持 | 可，仍須符合權利與核定要求 |
| `corroborated` | 至少兩個相互獨立來源支持 | 可，附來源與必要限制 |
| `owner-confirmed` | Chinwen 以親歷或治理權責確認 | 可標示為口述／Owner 核定口徑 |
| `public-record` | 已開啟並核對的政府、組織、合作方、新聞或影音公開頁面 | 可，保留來源歸因與適用範圍 |
| `context-only` | 僅支持時代背景 | 不得用來證明組織事件 |
| `lead-only` | 尚未查證的線索 | 不可 |
| `conflict` | 來源彼此矛盾 | 不可；列出差異待核定 |
| `blocked` | 受保密、權利、個資或證據缺口限制 | 不可 |

## Chinwen 核定的公開史料規則（2026-08-09）

- 可公開取得且已實際開啟、核對內容的歷史資料，可作為可信任的敘事來源，不強制再找第二個獨立來源。
- Chinwen 以親歷與治理權責核定的歷史，可進入正文，不強制指定第二覆核人；仍須保留核定日期與可追溯記錄。
- 搜尋結果摘要、無法開啟的頁面與未核對影片仍為 `lead-only`，不可僅憑摘要提升為公開史料。
- 公開可信任不等於可重製。圖片、影片、Logo、完整文章、逐字引言、個資與兒少素材仍須完成權利審查。
- 募款、財務、法律責任、跨專案累計、碳排與可能造成重大誤導的數字，仍須保留期間、母體、狀態、公式與去重規則。
- 華碩保密合約內容、位置與推測維持 `blocked`，不因發布 Gate 放寬而解除。

## 數字與影響力

- 分開記錄活動數據、估算係數、公式、結果、期間與資料版本。
- 不以產能、預期效益或個案數字代替年度實績。
- 碳排為方法約束下的估算；除非有第三方查證，不寫成認證或實測成果。
- 使用「約」「餘」「截至」時仍須保留原始口徑與期間。

## 衝突處理

保留所有有意義的來源、差異及查閱日期。不要靜默選擇較好寫的版本。若無法排除衝突，降低精確度或停止敘述，並交由 Chinwen 或適當治理角色核定。
